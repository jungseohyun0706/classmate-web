# 초대·로그인·설치 흐름

원본 요구서 9·10장, R05·R06·R17, T02·T04~T10·T42·T44·T46. 서버: `src/lib/invitations.ts`, `src/pages/api/invitations.ts`, `src/pages/api/join.ts`, `src/pages/api/join-info.ts`. 화면: `src/pages/i/[code].tsx`, `src/pages/install.tsx`, `src/lib/pendingInvite.ts`, `src/components/InviteCodeInput.tsx`, `src/components/timetable/InvitePanel.tsx`.

## 1. 초대 종류

| 종류 | 대상 | 수락 결과 | 발급 권한 |
|---|---|---|---|
| 학급 초대 (`homeroom`) | 소속 학급 `classes/{학교_학년_반}` | 소속 학급 신청(담임 승인 대기). 승인 학생이면 반 이동 신청 | 그 학급 담임 |
| 수업 초대 (`course`) | 수업반 `schools/{s}/courses/{id}` | 수강(`enrollments/{courseId}__{uid}`) — `invitePolicy`에 따라 바로 active 또는 승인 대기. **소속 학급은 바꾸지 않음** | 담당 교사 또는 관리 교사 |
| 예전 QR (`/join?c=&t=`) | 학급 또는 수업 그룹 | 기존 규칙 유지(10분 토큰). 그룹에 연결된 수업(`legacyGroupId`)이 있으면 수강도 생성 | 같은 학교 교사(기존) |

초대 코드는 8자(헷갈리는 문자 0·O·1·I·L 제외), 화면 표시 `XXXX-XXXX`, 링크 `/i/{code}`. 기본 만료 30일(1~180일), 사용 수 제한 기본 없음 — 여러 학생이 같은 코드를 쓰며 첫 학생이 쓰고 소진되지 않습니다. 회수하면 즉시 쓸 수 없습니다. 초대 문서는 클라이언트가 읽거나 쓸 수 없고 API로만 다룹니다.

## 2. 학생 흐름 (9-3 기본 흐름)

```
초대 링크 /i/CODE 열기
 → preview(로그인 불필요): 학교·대상(학급 'N학년 M반' / 수업 제목)·교사 이름·종류·상태만 (학생 명단·uid 없음)
 → 로그인 안 됨/익명 계정: 코드를 기기에 저장(pendingInvite, 7일) → /auth/login?next=/i/CODE (next는 같은 사이트 상대 경로만 허용)
 → 로그인됨: 현재 계정 이메일 표시, '이 계정으로 참여' / '다른 계정으로'
 → accept: 서버가 상태·학교·학기·종료·계정 종류를 다시 확인하고 트랜잭션으로 수강/신청 기록
 → 결과 화면: 수업 추가됨 / 승인 대기 / 이미 참여 / 학급 신청 대기 / 반 이동 신청 → '내 시간표 보기'
 → 학생 화면은 schools/{s}.scheduleRevision 변경을 구독해 시간표를 다시 받음
```

- 같은 코드를 두 번 수락하거나 버튼을 두 번 눌러도 같은 결과(`already`)이고, 사용 수는 처음 수락할 때만 늘어납니다.
- 수락으로 교사·관리자 권한을 얻을 수 없습니다(교사 계정은 403 `teacher-account`, 익명 403 `anonymous`).
- 가입 직후 프로필이 없는 계정이 수업 초대를 수락하면 `role:'student', status:'pending', classId:null` 프로필을 만들고 수강만 연결합니다. 소속 학급은 비워 두며 수업 교실·그룹을 소속으로 쓰지 않습니다.
- 학생 명단의 미가입 학생과 새 계정은 이름으로 연결하지 않습니다(명단 연결은 `/api/roster-import` link — 담임·담당 교사 확인).

### 상황별 처리 (9-2)

| # | 상황 | 처리 |
|---|---|---|
| 1 | 설치·로그인 완료 | 대상 확인 → 이 계정으로 참여 |
| 2 | 설치, 로그아웃 | 코드 저장 → 로그인 → 저장된 초대로 돌아와 참여(PWA 시작 화면 `/dashboard`에서도 이어짐) |
| 3 | 미설치 | 웹에서 그대로 참여 가능. 설치 안내는 초대 정보 아래 작은 카드(`/install?code=`) |
| 4 | 웹 브라우저 | 같은 흐름. 인앱 브라우저의 구글 로그인 차단 여부는 실기기 확인 필요(미검증) |
| 5 | 다른 계정으로 로그인 | 이메일 표시, '다른 계정으로' → 로그아웃해도 초대 유지, 시간표 캐시 삭제 |
| 6 | 이미 참여 | `already` — 같은 결과 화면 |
| 7 | 만료·회수 | `expired`/`revoked`/`used-up` 각각 다른 안내 + 새 초대 요청. 네트워크 오류·5xx는 '다시 시도'(만료로 표시하지 않음) |
| 8 | 다른 학교·학기·종료 수업 | `other-school`(403), `ended`(410: 수업 종료 또는 학기 종료) |

## 3. 설치 과정의 초대 복구 (9-4)

- 실제 배포 형태는 웹앱(PWA: `public/manifest.webmanifest`, `public/sw.js`)뿐입니다. 저장소에 스토어 주소·iOS 앱·`apple-app-site-association`이 없고, `public/.well-known/assetlinks.json`에 Android TWA 패키지명만 있습니다(스토어 등록 여부 확인 불가). 그래서 설치 화면은 스토어 버튼이나 '출시 예정' 문구를 보여 주지 않습니다.
- Android Chrome: `beforeinstallprompt`가 있을 때만 '설치' 버튼. 설치된 앱과 브라우저가 저장소를 공유하는 경우가 많아 저장된 초대가 이어질 수 있지만 단정하지 않습니다.
- iOS Safari: '공유 → 홈 화면에 추가' 단계 안내. 홈 화면 앱은 Safari와 저장소가 분리되어 자동 복원이 안 될 수 있으므로 **초대 코드(복사)와 '원래 초대 링크 다시 열기'**를 함께 보여 줍니다.
- 다시 열 때마다 서버가 유효성을 다시 검사합니다. URL에는 초대 코드 외 개인정보가 없습니다.
- 무차별 대입 제한: 같은 IP 실패 10분 30회, 같은 계정 실패 10분 10회, 같은 IP 전체 1분 300회(없는 코드·형식 오류만 실패로 셈 — 같은 학교 공인 IP에서 만료 코드를 연 학생 때문에 새 코드가 막히지 않게). 서버 메모리 기준이라 여러 서버 인스턴스 간에는 공유되지 않습니다(운영 전 확인 필요).
- 로그인 후 이동 주소(`next`)는 `/`로 시작하는 같은 사이트 경로만 허용합니다(임의 리디렉션 방지).

### 기기 저장 값

| 키 | 저장소 | 내용 | 수명 |
|---|---|---|---|
| `cm_pending_invite_v1` | localStorage | `{code, savedAt}` — 초대 코드만(개인정보 없음) | 7일, 수락·이미 참여·사용 불가 초대면 삭제 |
| `cm_pending_invite_resumed_v1` | sessionStorage | 같은 탭에서 같은 코드로 한 번만 자동 이동 | 탭 |
| `cm_tt_v1_<uid>` | localStorage | 본인 개인 시간표 자료 캐시(오프라인 표시용) | 로그아웃·계정 전환 시 삭제 |

- 서비스 워커(`public/sw.js`)는 `/i/{code}`, `/join?c=&t=`, `/install?code=` 화면을 캐시에 넣지 않습니다(초대 코드·입장 토큰이 캐시 키로 남지 않게). 버전을 올려 예전에 저장된 항목도 지웁니다.
- 로그인 화면: `next` → 저장된 초대 → 기존 기본 화면 순으로 이동. 프로필이 없는 계정은 저장된 초대가 있으면 그 초대로, 없으면 '학생이면 초대 코드 입력 / 선생님이면 교사 인증' 갈래 화면(예전에는 학생도 교사 인증 단계로 보내졌음).
- 가입 화면: 초대로 들어오면 학생 가입(이름·이메일·비밀번호·구글)을 먼저 보여 주고 가입 뒤 초대로 돌아갑니다. 초대 없이 들어오면 기존 교사 가입.
- 교사 QR·공유 링크의 origin은 교사가 연 브라우저 주소(`window.location.origin`)를 따릅니다(고정 도메인 설정 없음).

### 계정 상태별 처리 보강(검토 반영)

- 익명(둘러보기) 세션은 모든 학생 화면에서 '로그인 안 됨'으로 봅니다(로그인 next=현재 경로).
- 프로필 없는 계정: 로그인 화면은 `?next`가 초대 경로일 때만 초대로 이어가고, 보관된 초대만 있으면 '학생: 받은 초대로 이어서 참여 / 선생님: 교사 인증' 갈래를 보여 줍니다. 초대 화면도 '참여하면 학생으로 등록돼요' 안내와 '선생님이에요(교사 인증)' 버튼을 둡니다. 교사 인증이 끝나면 보관된 초대를 지웁니다.
- 승인 대기 배너는 실제 학급(또는 예전 그룹) 신청이 있을 때만(`status pending` && `classId` 있음) — 수업 초대로만 가입한 소속 없는 학생에게는 '소속 학급 없음'만 보입니다.
- 그룹 QR로 연결 수업에 들어올 때도 수업의 `invitePolicy`를 따릅니다(승인 필요면 승인 대기 + 담당·관리 교사 알림).
- 알림 중복 방지 id는 신청마다 다름(학생 문서의 `joinSeq` +1): 같은 신청의 재전송·더블 탭은 알림 1건, 거절 뒤 재신청·그룹에서 빠진 뒤 재참여는 새 알림.
- 학생은 자기 `studentId`(번호)·`joinSeq`를 클라이언트에서 바꿀 수 없음(명단 연결 후보 가로채기 방지) — 번호는 서버 경로(`/api/join`, 초대 수락, 반 이동 승인)로만.
- 서비스 워커 캐시는 `classmate-v3`. `?next`가 초대 화면인 로그인·가입 주소와 쿼리가 붙은 `/auth/*` 화면도 저장하지 않습니다.
- 로그인·가입·`/join` 폼은 `method="post"`이고 하이드레이션 전에는 제출 버튼이 꺼져 있습니다(전에는 연결 전 제출 시 이메일·비밀번호가 URL에 실림).

## 4. 예전 링크 호환 (T42)

- `/join?c=&t=`(학급·수업 그룹 QR)는 경로·파라미터·응답 모양을 유지합니다. 오류는 `code`로 구분(400/404/410/429/503)되어 화면이 '만료'만 보여 주지 않습니다.
- 신청 중(pending) 학생이 수업 그룹 QR을 찍으면 원래 학급 신청을 덮어쓰지 않고 `extraClassIds`에만 추가합니다(`joined-extra-pending`, H2 수정).
- 그룹에 연결된 수업이 있으면 그 수업 수강을 만들어 개인 시간표에 나타납니다(H1 서버 쪽 수정). 연결된 수업이 없으면 만들지 않습니다(그룹을 소속 학급처럼 쓰지 않음).
- 같은 반 재신청은 프로필만 갱신하고 교사 알림을 다시 보내지 않습니다(알림 문서 id 고정).

## 5. 교사 화면

- `/teacher/class-qr`: 학급 초대(오래 쓰는 코드, 권장)를 위에, 예전 10분 QR을 아래에 둡니다. 수업 그룹이면 수업 관리의 수업 초대로 안내합니다.
- `/teacher/courses/[id]`: 수업 초대 생성·목록(사용 수·만료·회수 상태)·회수.
- 학급 초대와 수업 초대는 제목·색·설명 문구로 구분합니다.

## 6. 미완료·운영 전 확인

- 실기기(iOS Safari·홈 화면 앱, Android Chrome·설치 앱, 카카오톡 인앱 브라우저) 동작은 확인하지 않았습니다.
- 스토어 앱 경로는 없습니다. TWA 패키지(`com.jungseohyun7.classmate`)의 스토어 등록 여부와 Digital Asset Links 검증은 운영자가 확인해야 합니다.
- 운영 도메인(classmate.kr)에서 `/i/{code}` 링크가 앱으로 열리는지(App Links)는 설정이 없어 웹으로 열립니다.
